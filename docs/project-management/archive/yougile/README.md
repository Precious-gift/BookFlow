# BookFlow YouGile Population Tooling (Archived)

> [!NOTE]
> **ARCHIVED / HISTORICAL EVALUATION SPIKE (Phase 7.2):** This directory contains historical planning documentation and CLI tooling created during an evaluation spike for YouGile. Operational Agile management has transitioned to the public [BookFlow Trello Board](https://trello.com/b/3BOlXBHK/bookflow-mvp-implementation), and the canonical backlog manifest resides in [`docs/project-management/backlog/`](../../backlog/).


## Contents

- `populate_yougile.py`: Executable Python CLI tool supporting offline `--mode dry-run` (default) and live `--mode live`.
- `backlog_manifest.json`: Canonical machine-readable backlog manifest extracted from `BOOKFLOW_MVP_BACKLOG_PACKAGE_v1.0.md` and Phase 7.1.x audits (1 MVP, 10 Epics, 28 Features / 32 entries, 41 Stages / 37 entries, 56 Sub-stages, 56 Tickets).
- `yougile_id_map.dryrun.json`: Isolated ID cache generated during offline simulated dry-runs.
- `yougile_id_map.live.json`: Isolated ID cache generated during live population runs.
- `population_verification_report.json`: Verification report generated by the population engine.

## Hierarchy & Workflow Architecture

The BookFlow backlog logical hierarchy (`MVP` → `Epic` → `Feature` → `Stage` → `Sub-stage` → `Ticket`) is decoupled from the Kanban workflow:

1. **Kanban Board Workflow Columns:**
   - `Backlog`: Initial intake column where all 56 tickets are placed in strict topological dependency order.
   - `Ready`: Tickets whose prerequisite tickets are 100% completed (`Done`) and verified.
   - `In Progress`: Actively being implemented by an engineer.
   - `Review`: Pull request open; code review and integration testing active.
   - `Done`: Acceptance criteria and validation gates verified.
   - `Blocked`: Impeded by technical blockers or prerequisite defects.
2. **Hierarchy Traceability on Each Task:**
   - **Title Prefix:** `[EP-XX | T-YY] Ticket Title` for instant visual Epic identification.
   - **Card Color:** Cards are visually color-coded by Epic across YouGile's palette.
   - **Structured Markdown Breadcrumb:** Every task description begins with an explicit 6-level logical breadcrumb (`MVP > Epic > Feature > Stage > Sub-stage > Ticket`).
   - **Prerequisite Gates Checklist:** Native interactive checklist on each task (`[ ] Prerequisite T-XX verified in DONE column`) enforcing the operational Definition of Ready.
   - **Acceptance Criteria & Validation Checklists:** Native interactive checklists for test and completion sign-off.

## Usage

### 1. Offline Verification and Dry-Run (Safe — Zero Network Calls)

Run offline validation of the backlog DAG (checks 56 tickets, mandatory fields, parent references, topological sorting, and cycle freedom):

```bash
python populate_yougile.py --verify-only
```

Run a full simulated dry-run:

```bash
python populate_yougile.py --mode dry-run
```

The dry-run simulates the creation of:
1. 1 Project: `BookFlow`
2. 1 Board: `BookFlow — MVP Implementation`
3. 6 Workflow Columns: `Backlog`, `Ready`, `In Progress`, `Review`, `Done`, `Blocked`
4. 56 Ticket Tasks: `T-01` through `T-56` in topological dependency order, all placed into the `Backlog` column

### 2. Eventual Live Population (Requires Explicit User Authorization)

Live population is **NOT** executed during Phase 7.2. When authorization is granted:

1. Obtain a YouGile Bearer API token from the company workspace.
2. Set the token in your environment (do not write it to disk or commit it):
   ```bash
   export YOUGILE_API_KEY="your-yougile-bearer-token"
   # or on Windows PowerShell:
   $env:YOUGILE_API_KEY="your-yougile-bearer-token"
   ```
3. Choose an explicit destination strategy:
   - **Option A: Populate into an existing Project and Board**
     Fill out `id_mappings.template.json` with the existing UUIDs for `project`, `board`, and workflow columns, then run:
     ```bash
     python populate_yougile.py --mode live --map-file docs/project-management/yougile/id_mappings.template.json
     ```
   - **Option B: Explicitly authorize creating a new Project and Board**
     ```bash
     python populate_yougile.py --mode live --create-new-project
     ```
   *(Note: Running `--mode live` without an explicit mapping file or without `--create-new-project` will safely abort to prevent silent project creation).*

### Safety & Reliability Features

1. **Strict Rate Limiting:** Enforces a client-side delay of 1.5s between requests (max 40 req/min), staying strictly below YouGile's documented 50 req/min limit.
2. **Schema-Backed Idempotency:** Every entity creation payload includes a deterministic `idempotencyKey` (`bookflow-project-bookflow`, `bookflow-board-mvp-implementation`, `bookflow-workflow-column-<name>`, `bookflow-ticket-T-XX`).
3. **Resumable Partial Failures:** The tool persists `yougile_id_map.json` after every successful creation. If an execution is interrupted, re-running will resume from the next uncreated entity with zero duplicate tasks.
4. **Credential Isolation:** The script strictly accepts API keys via the `YOUGILE_API_KEY` environment variable or `--api-key` command-line argument. No secrets are stored in code or repository files.
5. **Destination Safety Gate:** In live mode, destination targets must be explicitly specified via `--map-file` or authorized via `--create-new-project`; the script will never silently create projects.
